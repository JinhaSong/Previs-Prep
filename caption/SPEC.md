# 캡션 생성 규격서 (영어 캡션 + 한국어 번역)

> 3D 객체 검색 AI 학습 데이터 구축용 **텍스트(문장) 생성** 규격.
> 멀티뷰 렌더 이미지로부터 객체당 영어 설명문을 생성하고, 이를 한국어로 번역해
> **한/영 문장 쌍**을 만든다. 두 단계 모두 Apache-2.0 모델만 사용한다. (검증: 2026-08, ETRI)
>
> 검증 기준: 생성 캡션으로 **text→3D 검색 성능**을 측정해 공개 데이터셋(Cap3D)과 비교.
> 현 규격(v4)은 동일 갤러리·동일 인코더 조건에서 **Cap3D를 상회**한다.

## 1. 파이프라인 개요

```
멀티뷰 렌더(8뷰) ──> [1] Qwen2.5-VL-7B-Instruct ──> 영어 캡션
                                                      │
                                                      ├──> [2] Qwen3-8B ──> 한국어 캡션
                                                      │
                                                      └──> [3] 자동 검수 (형식·내용·의미)
```

**Cap3D 대비 구조 차이.** Cap3D는 [뷰별 BLIP-2 생성 → CLIP으로 최선 뷰 선택 → GPT-4로 통합]의
3단계다. 본 규격은 Qwen2.5-VL이 **멀티이미지 입력을 네이티브 지원**하는 점을 이용해
8뷰를 한 번에 입력하고 통합 캡션을 직접 생성한다. 즉 Cap3D의 GPT-4 통합 단계를
오픈 모델로 대체한 것이며, 상용 API 의존과 뷰 선택 단계가 사라진다.

## 2. 모델 및 라이선스

| 단계 | 모델 | 라이선스 | 비고 |
|------|------|----------|------|
| 영어 캡션 | `Qwen/Qwen2.5-VL-7B-Instruct` | Apache-2.0 | 멀티이미지 입력 |
| 한국어 번역 | `Qwen/Qwen3-8B` | Apache-2.0 | thinking 모드 off |
| 의미 검수 | `sentence-transformers/LaBSE` | Apache-2.0 | 번역쌍 판별 전용 |

> **기술이전 적합성**: 전 구간 Apache-2.0으로, 상용 배포 및 생성 결과물 활용에 제약이 없다.
> (참고: NLLB-200은 CC-BY-NC이므로 본 규격에서 배제했다.)

## 3. 입력 규격

| 항목 | 값 |
|------|-----|
| 뷰 개수 | **8뷰** (전체 렌더에서 균등 간격 선택) |
| 이미지 크기 | 448×448 |
| 배경 처리 | RGBA → **흰 배경 합성** (alpha_composite) |
| 입력 경로 | `{render_root}/{uid}/*.png` |

## 4. 영어 캡션 규격

### 4.1 생성 파라미터

| 항목 | 값 |
|------|-----|
| 디코딩 | greedy (`do_sample=False`) — 대표문의 재현성 확보 |
| max_new_tokens | 80 |
| 복수 문장(`--num_captions N`) | 1번째 greedy(대표문) + 나머지 nucleus sampling(`top_p=0.9, temp=0.9`), 중복 제거 |

### 4.2 프롬프트 설계 근거

프롬프트는 **Cap3D 실제 캡션 5개를 few-shot 예시**로 제시하고 5개 규칙을 준다.
핵심은 **규칙 2(개체 식별성)** 이며, 이는 실험으로 도출된 것이다.

초기 버전(v3)은 "짧고 간결하게"를 강조했더니 Cap3D 대비 **R@1이 3.58%p 낮았다.**
원인은 압축 과정에서 같은 종류의 다른 객체와 구분되는 단서(정확한 색 조합, 패턴,
부착물, 표면 문구)가 함께 사라진 것이었다. 이를 "**같은 종류의 다른 객체와 구별될
만큼 구체적으로**"로 바꾸고 길이를 15–20단어로 지정한 v4에서 성능이 역전됐다.

> 시사점: 3D 검색용 캡션의 품질 지표는 "간결함"이 아니라 **식별성(discriminability)** 이다.

### 4.3 수용 기준

| 항목 | 기준 | v4 실측 |
|------|------|---------|
| 생성 실패율 | ≤ 1% | 0.0% |
| 형식 위반 (`is shown`, `3D model of`, 배경 언급 등) | ≤ 2% | 충족 |
| 모호 명명 (`a rectangular object` 등) | ≤ 3% | 충족 |
| 평균 단어 수 | 12–20 | 15.1 (Cap3D 12.5) |
| **text→3D 검색 R@1** | **Cap3D 이상** | **28.77% vs Cap3D 27.88%** (+0.89%p) |

> 검색 평가 조건: 갤러리 12,935개(중간 집계 시점), Uni3D-g 3D 임베딩 고정,
> EVA02-E-14-plus 텍스트 인코더, 동일 쿼리 집합. 세 캡션 소스를 동일 조건에서 비교.

## 5. 한국어 캡션 규격

### 5.1 번역 규칙 (프롬프트에 명시)

1. 반드시 한국어로만 출력 — 한자·중국어·일본어 금지
2. 브랜드명과 객체에 실제로 적힌 문구는 **영문 원문 유지** (예: `"HOLY BIBLE"`, `Band-Aid`)
3. **명사구로 종결** (`~이 있는 갈색 의자`) — `~입니다`, `~있다` 금지
4. 색상·재질·형태·부착물 누락 금지
5. 직역투(`~되어진`, `~와 함께`) 금지
6. 번역문 한 줄만 출력

여기에 **도메인 few-shot 5쌍**을 붙인다. 예시는 실제 오역이 났던 어휘를 고정하는
역할을 한다(`spine`→**책등**(척수 아님), `hardcover`→**양장본**, `knob`→**노브**).

### 5.2 모델·프롬프트 선정 실험

동일 40쌍에 대한 3-way 비교 (LaBSE 의미 유사도 + 자동 형식·내용 검수):

| 구성 | 정상률 | 한자 혼입 | 종결어미 위반 | LaBSE cos p10 |
|------|--------|-----------|---------------|---------------|
| Qwen2.5-7B, 규칙만 (v1) | 27.5% | 7 | 23 | 0.779 |
| Qwen2.5-7B, few-shot (v2) | 85.0% | 3 | 0 | 0.692 |
| **Qwen3-8B, few-shot (v2)** | **92.5%** | **0** | **0** | **0.775** |

**해석**: few-shot 도입이 27.5→85%로 대부분을 해결했고(프롬프트 기여), 모델을
Qwen3로 올려 85→92.5%를 추가로 얻었다(모델 기여). Qwen2.5는 중국어 중심 학습의
영향으로 한자 혼입이 끝까지 남았으나 Qwen3-8B에서는 0건이다.

> v1의 대표적 실패: `빨간的缘边和米色的页面的打开的书` (문장 전체 중국어),
> `Brown`→`ROWN색` (토큰 깨짐), `spine`→`척수` (도메인 오역).

### 5.3 자동 품질 게이트 (생성 시점)

생성 직후 결함을 검사해 **결함 건만 재시도**한다. 검사 항목:

| 결함 | 판정 | 도입 배경 |
|------|------|-----------|
| `cjk` | 한자·가나 포함 | Qwen2.5 다발 |
| `no_hangul` | 한글 없음 | 번역 실패 |
| `length` | 4자 미만 / 200자 초과 | 절단·폭주 |
| `verb_ending` | `~입니다.`/`~있다.` 종결 | 규칙 3 위반 |
| `fewshot_copy` | few-shot 답변과 문자 3-gram 자카드 ≥ 0.30 | **형식 검사를 통과하므로 별도 신호 필요** |
| `meta_leak` | `번역`, `：` 포함 | `~의 한국어 번역은:` 누출 |
| `foreign` | 키릴·그리스·타이 문자 포함 | 실측 `свет browm색` |
| `latin_left` | 미번역 영어 잔존 (인용문구·고유명사 제외) | 실측 `stylized한` |
| `color_lost` | 원문 색상어가 한국어에 대응 없음 | **검색 1차 속성** |
| `quote_lost` | 원문 인용문구가 번역문에 없음 | 규칙 2 위반 |

### 5.4 재시도 전략 — few-shot 유지/제거를 실패 유형별로 나눈다

few-shot 은 **정반대 실패 모드의 트레이드오프**를 갖는다(동일 40쌍 실측):

| | few-shot 유지 | few-shot 제거 |
|---|---|---|
| 예시 복사 | 1.73% | **0%** |
| 종결어미·문체 위반 | **0%** | 27.5% |

어느 한쪽으로 고정할 수 없으므로, **기본은 few-shot 으로 생성하고 복사·의미 실패가
감지된 건만 few-shot 없이 재번역**한다. few-shot 없이 쓸 때의 어휘 흔들림은
GLOSSARY(도메인 용어 대응표)를 규칙에 직접 넣어 보완한다.

재시도는 다음 순서로 최대 3회 시도하며, **점수가 개선될 때만** 교체한다.

1. few-shot 제거 (복사·의미 오류 해소)
2. few-shot 제거 + sampling (1이 실패할 때 다양성 부여)
3. few-shot 유지 + sampling (한자·종결어미 해소)

**결함에는 경중이 있다.** '다른 물건을 서술'(복사·의미)은 데이터셋을 오염시키지만
종결어미 위반은 문체 문제일 뿐이다. 초기 구현은 "재시도가 완전히 깨끗할 때만 교체"
했는데, 그 결과 *종결어미만 어긋난 올바른 번역*을 버리고 *전혀 다른 물건*을 유지하는
역효과가 났다(최악 6건 중 4건). 심각도 가중 점수로 바꾼 뒤 6건 전부 교정됐다
(LaBSE cos 0.25 → 0.84).

```
_SEVERITY = {fewshot_copy 100, no_hangul 100, meta_leak 50,
             cjk 20, foreign 20, length 20, latin_left 15,
             color_lost 15, quote_lost 10, verb_ending 5}   # + 의미 미달 시 100
```

### 5.5 보정 모드 (`--repair`)

검수 기준이 강화될 때마다 전량 재생성(수 시간)하는 것은 낭비이므로, **기존 산출물에서
게이트를 통과하지 못한 건만 재번역해 병합**하는 모드를 둔다. 정상 건은 원본을 보존하고,
점수가 개선될 때만 교체하며, 배치마다 `.partial` 에 기록해 중단 후 재개할 수 있다.
인수 기관이 자체 기준으로 재검수·보정하는 경로로도 그대로 사용할 수 있다.

```bash
python caption/qwen_translate_ko.py --repair "caps_ko_s*.jsonl" --in x --out caps_ko_fixed.jsonl
```

## 6. 한/영 정합성 검수 (`caption/qc_bilingual.py`)

세 층위로 나눠 검사한다. 층마다 잡히는 실패 유형이 다르다.

| 층위 | 방법 | 잡는 실패 |
|------|------|-----------|
| **형식** | 규칙 기반 | 한자 혼입, 한글 부재, 종결어미, 메타 누출 |
| **내용** | 숫자·인용문구·색상어 대응 사전 | 수량 소실, 표면 문구 소실, 색상 누락/오역 |
| **의미** | LaBSE EN↔KO 코사인 | 오역, 문장 통째 치환, 내용 누락 |

**층위 분리가 필요한 이유**: v1은 LaBSE cos 중앙값이 0.859로 양호했으나 실제로는
사용 불가 수준이었다. LaBSE는 문체·표기 규칙 위반을 벌하지 않기 때문이다.
반대로 `fewshot_copy`는 형식·내용 검사를 모두 통과하고 의미 검사에서만 걸린다.
**어느 한 층만으로는 불충분하다.**

### 수용 기준

| 항목 | 기준 |
|------|------|
| 형식 결함률 | ≤ 3% |
| 한자 혼입 | **0건** |
| LaBSE cos 중앙값 | ≥ 0.80 |
| LaBSE cos < 0.60 (오역 의심) | ≤ 3% → **전량 사람 검수** |

`--out` 으로 결함 건만 jsonl 추출 → 사람 검수 대상을 좁힌다.

## 7. 출력 포맷

```jsonl
{"uid": "...", "category": "...", "n_views": 8,
 "caption": "A worn hardcover book with a brown cover and a red bookmark ribbon.",
 "captions": ["...", "..."],            // --num_captions > 1 일 때만
 "caption_ko": "갈색 표지와 빨간 책갈피 끈이 달린 낡은 양장본 책",
 "ko_sim": 0.8612}                      // qc_bilingual 실행 시 부여
```

`caption`은 항상 **대표문 1개**(greedy)이므로, 복수 문장을 쓰지 않는 소비자도
스키마 변경 없이 그대로 읽을 수 있다.

## 8. 실행

```bash
# 1) 영어 캡션 (GPU 1장당 1프로세스, --shard 로 분산)
python caption/qwen_caption.py \
  --uid_list uids.txt --render_root /data/renders \
  --out caps_s0.jsonl --shard 0 --num_shards 4

# 2) 한국어 번역 (resume 지원, 중단 후 재실행 가능)
python caption/qwen_translate_ko.py \
  --in "caps_s*.jsonl" --out caps_ko.jsonl --batch 16

# 3) 결함 건만 재번역해 보정 (선택, 게이트 강화 후 재적용 시)
python caption/qwen_translate_ko.py \
  --repair "caps_ko*.jsonl" --in x --out caps_ko_fixed.jsonl

# 4) 샤드 병합 → 인도용 단일 데이터셋 (중복·실패 제거, 커버리지 보고)
python caption/merge_captions.py \
  --in "caps_ko_fixed*.jsonl" --out dataset.jsonl \
  --require_ko --target 20430 --min_per_class 20

# 5) 한/영 정합성 검수 → 결함 건 추출 (병합 결과에 대해 반드시 재실행)
python caption/qc_bilingual.py \
  --in dataset.jsonl --out defects.jsonl
```

> 순서 주의: **병합은 검수가 아니다.** 샤드별로 검수를 통과했더라도 병합 과정에서
> 중복 해소·필드 정리가 일어나므로, 인도 판정은 항상 병합된 최종 파일 기준으로 한다.

## 9. 대규모 처리 시 권고 (10만~100만 객체)

본 규격은 **품질 기준과 재현 절차**를 정의하며, 처리량 확보는 구축 주체의 몫이다.
현 구현은 HuggingFace `transformers` 기반으로 정확성·검증 용이성을 우선했다.
대규모 적용 시 아래를 권고한다. **단, 어떤 최적화를 적용하든 §4.3·§6의 수용 기준을
동일하게 충족해야 하며, 표본 검수로 이를 입증해야 한다.**

| 항목 | 권고 |
|------|------|
| 추론 엔진 | vLLM / SGLang 등 continuous batching 도입 (동일 가중치·동일 프롬프트 유지) |
| 병렬화 | `--shard/--num_shards` 로 GPU·노드 단위 분산 (본 구현에 내장) |
| 중단 복구 | 출력 jsonl 기반 resume 내장 — 재실행 시 완료분 자동 skip |
| 검수 | 전량 자동 검수 + 결함 건 및 무작위 표본 사람 검수 |

## 10. 운영 시 반드시 지킬 것 — 실패가 성공처럼 보이는 사례

본 파이프라인 구축 중 **로그는 정상인데 산출물이 무효/정체**인 사고가 세 차례 있었다.
모두 산출물을 직접 세어보는 검수로만 발견됐다.

| 사고 | 증상 | 원인 | 조치 |
|------|------|------|------|
| GPU 아키텍처 불일치 | 10,215건이 `✓ 저장` 로그와 함께 전량 무효 | RTX 5080(sm_120)에 torch cu124 — 해당 커널 없음 | cu128 빌드 고정 (dockerfile `TORCH_CUDA`) |
| CPU 조용한 폴백 | 진행 0건, 로그는 정상 | 컨테이너 device cgroup 초기화 → `device_map="auto"` 가 CPU 선택 | 시작 시 `torch.cuda.is_available()` 확인 후 **즉시 중단** |
| 중복 생성 | 진행률 18,534 로 표시, 실제 고유 16,354 | resume 이 자기 출력 파일만 확인 | `--done_from` 으로 다른 산출물까지 합쳐 resume |

**따라서 진행률 로그를 완료 판정 근거로 삼지 말 것.** 판정은 항상
(1) 고유 uid 개수, (2) `qc_bilingual.py` 결함률, (3) 검색 성능 — 셋으로 한다.

> 규모가 커지면 표본 검수는 체계적 결함을 놓친다. few-shot 복사는 40개 표본에서
> 1건(2.5%, 노이즈로 보임)이었지만 15,752건 전수에서는 체계적 결함이었다.
> **부분 산출물이 쌓이는 즉시 전수 자동 검수를 돌릴 것.**
